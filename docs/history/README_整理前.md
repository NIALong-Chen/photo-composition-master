## 已讨论的能力范围

| 能力 | 预期表现 | 阶段 |
| --- | --- | --- |
| 实时画面理解 | 识别人脸、人物、主体及背景；进一步分析身体、地平线和视觉显著区域 | 基础到增强 |

| 即时指导 | 提示向左、向右、抬高、降低；进一步提示靠近、后退及主体在画面中的位置 | 基础到增强 |
| 状态反馈 | 构图合适时显示直观状态，例如提示变绿；后续考虑构图评分 | 基础到增强 |
| 人像指导 | 分析站姿、头肩方向、手臂/手部位置及画面裁切，给出具体且易执行的 Pose 建议 | 1.0 后的下一阶段重点 |

## 技术架构

```text
Android 摄像头
  → CameraX：预览、实时图像分析、拍照
  → 人物/主体/背景识别
  → AI 构图分析与摄影规则/风格知识
  → 屏幕箭头、文字和状态提示
  → 下一阶段：精细化人物 Pose 指导
  → 更后续：风景构图、语音提示、自动拍摄
```

**CameraX 的定位**：Google 的 Android 相机开发库，是获取相机预览帧、运行图像分析并执行拍照的基础设施。它本身不是 AI 构图模型，也不是摄影 Skill。

**AI 构图模型与算法**：负责理解画面主体和空间关系，依据构图规则生成建议。具体模型、端侧推理方案、帧率与性能目标尚待选型和验证。

**摄影 Skill / 知识库**：用于沉淀摄影规则、提示策略和风格偏好，也可辅助 Codex 开发；它不等同于用户最终使用的 App。最终产品应在 Android 手机上直接运行。

此前讨论过的组合可概括为 **CameraX + AI 构图模型 + 摄影 Skill → Android App / APK**。开发 CameraX 功能时可参考 [Google CameraX 官方文档](https://developer.android.com/media/camera/camerax/architecture)及此前提及的 [CameraX Skill](https://developer.android.com/agents/skills/camera/camerax/skill)。

## 开发阶段

### 第一阶段：可运行的 MVP

1. 建立 Android 相机页面：CameraX 实时预览、图像分析和手动拍照。
2. 在取景画面中识别人物，确定其大致位置与画面中的占比。
3. 实现三分法和基础视觉重心分析，输出简单、稳定的构图状态。
4. 在屏幕上给出上下左右移动提示；达到基本构图条件时显示“可以拍”或绿色状态。
5. 用真实人物及漫展/COS 人像场景验证提示是否易懂、及时且不会频繁抖动。

MVP 的重点是跑通“实时取景 → 人物识别 → 基础构图判断 → 即时提示 → 拍照”的完整链路。

### 第二阶段：精细化人物 Pose 指导（下一阶段重点）

- 在 1.0 的人物定位基础上加入身体关键点、头肩朝向与四肢位置分析。
- 先针对单人站姿和半身照，给出具体、可执行的建议，例如调整肩膀角度、手臂位置、视线方向或避免关节被画面边缘裁切。
- 结合漫展返图 / COS 人像样本验证建议是否适合服装、道具和人物意图；低置信度时不强行评价姿势。
- 让 Pose 提示与构图提示协调，同一时刻只突出最重要的一项调整。

### 第三阶段：风景构图与场景增强

- 增加独立的风景拍摄模式，分析地平线、主体位置、前中后景、留白及引导线。
- 在不同风景样本中验证三分法、居中对称等规则的适用条件，而不是共用人像阈值。
- 继续扩展人物拍摄的背景干扰提醒及更细的构图建议。

### 后续探索：拍摄体验增强

- 评估语音提示，减少摄影者持续盯着文字的负担。
- 探索 AI 美学模型和构图评分，并用真实拍摄样本校准。
- 在构图达标、主体状态合适且画面稳定时，探索可关闭的自动拍摄。

## 下一步开发入口

先确认目标 Android 设备和最低系统版本，再搭建 CameraX 的预览、分析、拍照闭环。随后选定适合端侧运行的人物检测方案，建立一组真实取景样本，定义基础构图判断与提示频率。每个阶段均以真机拍摄体验为准，避免提示遮挡主体或在连续帧间来回跳变。
